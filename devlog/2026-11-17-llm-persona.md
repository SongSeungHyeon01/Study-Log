# 2026-11-17 논문 읽기: LLM Generated Persona is a Promise with a Catch

## 논문 정보
| 항목 | 내용 |
|---|---|
| 제목 | LLM Generated Persona is a Promise with a Catch |
| 저자 | Ang Li, Haozhe Chen, Hongseok Namkoong, Tianyi Peng (NYU, Columbia, Princeton) |
| 게재처 | NeurIPS 2025 Position Paper Track, pp. 73875–73884 |
| 링크 | [proceedings.com PDF](https://www.proceedings.com/content/085/085713-2226open.pdf), DOI 10.52202/085713-2226 |
| 공개 자료 | 생성한 페르소나 약 100만 개 (Hugging Face `Tianyi-Lab/Personas`) |
| 읽은 날 | 2026-11-17 |

새 방법을 내는 논문이 아니라 포지션 페이퍼다. 문제를 실험으로 보여 주고 "이 분야를 제대로 연구해야 한다"고 주장한다.

## 한 줄 요약
LLM에게 페르소나(가상 인물 프로필)를 많이 지어내게 할수록 시뮬레이션 결과가 현실에서 멀어지고 한쪽(주로 진보 쪽)으로 쏠린다. 페르소나 생성을 감으로 하지 말고 하나의 연구 분야로 다뤄야 한다.

## 배경
- 페르소나: 나이, 성별, 인종, 지역, 직업, 성격, 정치 성향 등을 적은 가상 인물 프로필
- 페르소나를 준 LLM에게 설문을 풀게 해서 사람 설문을 대신하려는 시도가 많다. 이렇게 만든 응답자를 silicon sample이라고 부른다.
- LLM으로 페르소나를 만드는 이유
  - 실제 사람 데이터는 비싸고 개인정보 규제가 있다.
  - 인구조사는 항목별 분포만 있고 항목끼리의 결합 분포가 없다.
  - 가치관, 생활 방식 같은 주관적 속성이 공개 데이터에 없다.
- 지금까지는 페르소나를 더 많이, 더 다양하게 만드는 데만 집중했고, 실제 인구의 의견을 제대로 재현하는지는 평가하지 않았다.

## 페르소나 생성 방식 4단계
오른쪽으로 갈수록 LLM이 지어내는 내용이 많아진다.

| 단계 | 만드는 법 | LLM 관여 |
|---|---|---|
| Meta | 인구조사국의 결합 분포(나이·성별·인종·주)에서 샘플링 | 없음 |
| Objective Tabular | 소득·학력·직업·산업 추가, 인구조사국의 정해진 카테고리에서만 선택 | 보기 중 선택 |
| Subjective Tabular | Big Five 성격, 정치 성향, 종교, 여가, 버릇 등을 자유롭게 채움 | 자유 생성 |
| Descriptive | Meta만 주고 이야기 형식 프로필을 쓰게 함 | 전부 생성 |

- 주마다 Meta 1,000명을 샘플링하고 단계마다 1,000명씩 생성했다.
- 모델은 오픈소스 6개(Athene-70B, Llama 3.1 8B/70B, Mixtral-8x7B, Nemotron-70B, Qwen2.5-72B)다. 지시 튜닝만 한 모델과 RLHF 모델, 미국 모델과 미국 외 모델을 섞었다.
- 시뮬레이션은 "편향 없이 페르소나에 충실하게 답하라"는 지시, 페르소나, 객관식 질문을 한 번 넣고 보기를 고르게 한다. 고른 답을 세어 분포를 만든다.
- 중립성을 강조하는 프롬프트 변형도 써 봤지만 결과는 거의 같았다.

## 실험 결과
### 1. 미국 대선 (2016, 2020, 2024)
- 2024년, Llama 3.1 70B로 생성과 시뮬레이션을 모두 했을 때
  - Meta가 실제 결과에 가장 가까웠다.
  - LLM 생성 내용이 늘수록 민주당 쪽으로 이동했다.
  - Descriptive에서는 50개 주가 모두 민주당 승리로 나왔다.
- 학습 데이터에 결과가 있는 2016, 2020년도 똑같이 왼쪽으로 쏠렸다. 과거 결과를 안다고 편향이 상쇄되지는 않는다.
- 정렬 점수는 `1 − W(p̂, p)`(W는 시뮬레이션 지지율과 실제 득표율의 Wasserstein 거리)다. 생성 모델과 시뮬레이션 모델을 바꿔 가며 교차 실험했는데 모든 조합에서 같은 경향이었다. 특정 모델만의 문제가 아니다.
- 예외로 Yi-34B Chat은 오른쪽으로 쏠렸다(부록). 방향은 모델마다 다를 수 있다는 뜻이다.

### 2. 다른 분야 질문 9개 (정답 데이터 없음)
기후, 소비, 교육, 엔터테인먼트, 기술 질문에서 LLM 생성 내용이 많아질수록 다음 쪽으로 기울었다.
- 싼 차보다 비싼 친환경 차
- STEM보다 인문학 전공
- "트랜스포머"보다 "라라랜드"
- 화석연료보다 재생에너지, 규제 완화보다 환경 규제

자동차 회사가 전기차 수요를 과대평가하는 식으로 실제 의사결정이 틀어질 수 있다고 경고한다.

### 3. OpinionQA (Pew 설문, 실제 응답 분포 있음)
- 앞 500문항, 15개 주제에서 4종 페르소나 간 정렬 점수 분산을 봤다.
- 분산이 큰 주제: 젠더 관점 0.77, 정치 성향 0.65, 총기 0.44
- 분산이 작은 주제: 2050년 미국 전망 0.05, 젠더와 리더십 0.10
- 논쟁적인 주제일수록 페르소나를 어떻게 만드느냐에 결과가 크게 좌우된다.

## 페르소나 자체 분석
- TextBlob 감성 분석: LLM이 내용을 많이 쓸수록 극성이 긍정적으로, 주관성이 높게 나왔다.
- 워드클라우드: "love", "proud", "family", "community", "education", "heritage"가 많고 어려움이나 갈등을 나타내는 단어는 거의 없었다.
- 저자 해석: LLM은 모든 사람을 낙관적이고 공동체적이고 잘 사는 사람으로 그린다. 이 인물상이 사회 이슈 응답을 한쪽으로 끌고 간다.

## 저자가 제안하는 방향
1. 페르소나에 꼭 필요한 정보 찾기: 인구통계, 심리, 행동, 맥락 중 무엇이 결과를 좌우하는지, 어떤 형식으로 넣어야 하는지
2. 실제 인구에 맞게 보정하기: 흩어진 데이터로 결합 분포를 복원하고 목표 인구에 맞추는 샘플링·보정 방법
3. 오픈 벤치마크와 데이터셋: 평가용, 학습용, 바로 쓸 수 있는 페르소나 라이브러리를 겸하는 "페르소나판 ImageNet"
4. AI 연구자와 사회과학자, 도메인 전문가의 협업

## 반대 의견에 대한 답
- "실제 데이터만 써야 한다"는 쪽 근거: Park et al. 2024는 1,000명 이상 인터뷰로 정확도 85%, Toubia et al. 2025는 2,000명 이상, 500문항으로 held-out 정확도 88%
- 저자 반박: 성능은 인정하지만 비용과 윤리 문제가 크다. Park et al.은 데이터를 공개하지 못했고 Toubia et al.은 참가자 보상에 약 10만 달러를 썼다.
- 합성 페르소나 연구는 실제 데이터를 대체하는 게 아니라 보완하는 관계라는 입장

## 기존 연구와 다른 점
기존 LLM 편향 연구는 페르소나가 주어진 뒤 시뮬레이션 단계의 편향을 봤다. 이 논문은 그 앞, 페르소나를 생성하는 단계에서 생기는 편향을 따로 떼어 보여 줬다고 주장한다.

## 비판적으로 볼 점
- 생성 모델과 시뮬레이션 모델이 같은 계열이라 쏠림의 원인이 페르소나 내용인지 시뮬레이션 모델의 해석인지 완전히 분리되지 않는다. 교차 실험으로 일부 보완했다.
- 핵심 수치가 표로 정리돼 있지 않고 그림으로만 나온다. 9개 질문 실험은 정답 없는 정성 비교다.
- 70B급 이하 오픈소스 모델만 썼고 상용 최신 모델은 없다.
- 보정 방법이나 벤치마크는 제안만 하고 구현하지 않았다. 포지션 페이퍼 형식의 한계다.
- TextBlob은 단순한 사전 기반 감성 분석기라 근거로는 가볍다.

## 읽다가 궁금했던 것
### 질문: 내 상황에 투영해서 설명하면 나는 페르소나를 어떻게 써야 하나?
내 상황은 학생 개발자이고, Claude로 개발하며, 학교 관련 sLLM 서비스를 만들고 창업 프로그램 IR 발표를 준비하는 중이다.

### 답변 1: 아이디어 검증과 IR 자료에는 숫자 근거로 쓰지 않는다
- "타깃 사용자 페르소나 100명에게 이 서비스 쓰겠냐고 물어보면 시장 조사가 되겠다"는 유혹이 생긴다.
- 이 논문대로라면 LLM 페르소나는 긍정적이고 진보적인 쪽으로 쏠린다. 새 서비스나 AI 서비스에 "써 보겠다"는 답이 실제보다 많이 나올 가능성이 크다.
- "페르소나 시뮬레이션에서 78%가 사용 의향" 같은 숫자를 IR에 넣으면 "그거 LLM이 답한 거죠?"라는 질문에 방어할 수 없다.
- 대신 이렇게 쓴다.
  - 실제 인터뷰나 설문 전에 질문지를 다듬는 연습 상대로 쓴다. 어떤 반론이 나올지, 어떤 질문이 애매한지 미리 본다.
  - 사용자 유형은 학교 통계나 실제 학생 분포 같은 실제 자료로 정한다.
  - IR에 넣는 숫자는 실제 사람 5~20명 인터뷰나 설문으로 받는다.

### 답변 2: 서비스 테스트에는 쓸 만하지만 방식이 중요하다
의견 분포를 맞히는 게 아니라 다양한 입력을 만드는 용도라 논문의 경고가 덜 적용된다. 그래도 방식은 이렇게 한다.

| 하지 말 것 | 할 것 |
|---|---|
| "다양한 대학생 페르소나 50명 만들어줘"처럼 자유 서술로 생성 | 학년, 전공, 유학생 여부, 기술 숙련도 같은 항목과 보기 목록을 내가 정하고 조합을 코드로 샘플링 |
| LLM이 성격, 사연, 취미까지 지어내게 함 | 테스트에 필요한 속성만 넣음 (예: "한국어가 서툰 유학생", "마감 앞둔 4학년") |
| 생성된 질문만으로 테스트 | 실제 학생 질문 로그나 지인 질문을 섞어 비교 |

논문에서 LLM이 내용을 많이 지어낼수록 인물이 다 긍정적이고 비슷해졌다. 테스트에서는 화난 사용자, 엉뚱하게 묻는 사용자, 오타 많은 사용자 같은 까다로운 사람이 빠진다는 뜻이라 치명적이다. 까다로운 유형은 내가 직접 보기 목록에 넣어야 한다.

### 답변 3: 하네스에 넣는다면 근거와 맞대는 단계를 붙인다
가상 사용자 QA 에이전트를 하네스로 만든다면 앞서 하네스 스킬에 넣은 원칙과 이어진다.
- 페르소나 속성은 `scripts/`에서 정해진 목록으로 샘플링한다. [HarnessCompass](2026-11-09-harness-compass.md)의 위치 규칙처럼 결정적인 작업은 코드에 둔다.
- 페르소나가 낸 피드백은 실제 실행 로그나 실제 사용자 반응으로 뒷받침될 때만 반영한다. 하네스 스킬 Phase 7-1 실패 회고의 근거 대조 규칙과 같다.
- 페르소나가 "좋아요"라고 한 건 근거로 치지 않는다. 이 논문의 긍정 편향 때문이다.

### 정리
페르소나는 "무엇이 나올 수 있나"를 찾는 데 쓰고 "얼마나 많은 사람이 그럴까"를 재는 데는 쓰지 않는다. 질문지 다듬기, 테스트 입력 만들기, 반론 미리 보기에는 좋다. 수요 예측, 선호도 비율, IR 숫자는 실제 사람에게서 받는다.

## 생각해 볼 점
- 앞서 읽은 하네스 논문들과 결론이 같다. [EVO-HARNESS](2026-11-05-evo-harness.md)에서는 모델의 자기 판단 피드백이 해가 됐고, [HarnessCompass](2026-11-09-harness-compass.md)는 1인칭 보고를 궤적으로 검증했다. LLM이 스스로 만든 내용은 외부 근거로 보정하지 않으면 한쪽으로 쏠린다.
- LLM 글이 긍정적이고 비슷해진다는 점은 [AI 언어 이해도 논문](2026-10-27-ai-language-intelligibility.md)에서 본 모델이 쓰는 글의 특징과도 연결해 볼 만하다.
